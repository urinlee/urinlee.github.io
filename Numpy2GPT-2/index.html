1. LLM의 전체 흐름 이해

먼저 자료를 읽고 GPT와 대화하면서 LLM의 전체 구조부터 이해해 보기로 했다.

앞의 문맥을 보고 뒤에 나올 토큰을 예측하는 것. 내가 이해한 생성형 LLM의 기본 동작이다.

토큰 → 임베딩·위치 정보 → 트랜스포머 블록 × N → logits → 다음 토큰

조금 더 나누면 다음 과정을 거친다.

  1. 토큰화
  2. 임베딩
  3. 위치 인코딩
  4. Transformer 연산
  5. logits 출력
  6. 확률로 만들기(Softmax)
  7. 샘플링
  8. 디코딩

Transformer 연산에서는 인코더와 디코더가 맡는 역할을 나눠 살펴본다.

아래의 토큰 분할, ID, 벡터, 점수와 확률은 이해를 돕기 위한 가상의 예시다. 실제 모델의 출력은 아니다.

1.1. 토큰화

텍스트를 모델이 다루는 단위인 토큰으로 쪼갠다. 토큰의 기준은 모델마다 다르며, 한 토큰이 꼭 한 단어인 것은 아니다.

예시

“나는 밥을 먹었다”를 쪼개고, 각 토큰을 ID로 바꾸면 다음처럼 나타낼 수 있다.

문장    나는 밥을 먹었다
토큰    ["나", "는", " 밥", "을", " 먹", "었다"]
토큰 ID [10, 11, 20, 21, 30, 31]

1.1.1. BPE

BPE는 문자나 바이트 같은 작은 단위에서 시작해, 학습 데이터에서 자주 나오는 인접한 토큰 쌍을 반복해서 병합하는 방식이다. 실제 입력을 나눌 때는 이렇게 학습한 병합 규칙을 사용한다.

예시

c a t에서 c + a, ca + t 순으로 병합 규칙을 배웠다면 c a t → ca t → cat이 된다. 처음에는 문자 단위였지만 자주 등장하는 조합이 하나의 토큰이 된 것이다. BPE 동작 참고

1.2. 임베딩

각 토큰에는 고유한 ID가 있다. 이 ID를 크기나 의미를 가진 수치로 쓰지는 않는다.

해당 ID에 대응하는 실수 벡터를 가져오는 것을 임베딩이라고 한다.

1.2.1. Embedding Table

토큰 ID마다 대응하는 벡터를 저장한 표다. 벡터는 학습을 통해 토큰의 특징이나 의미적 유사성 등을 담게 된다.

예시

토큰 ID를 기준으로 아래 표에서 벡터를 가져온다.

토큰 토큰 ID 가져올 벡터
나 10 [0.2, -0.4, 0.7]
는 11 [0.1, 0.3, -0.2]
밥(앞 공백 포함) 20 [-0.5, 0.8, 0.1]

같은 토큰 ID라면 처음 가져오는 벡터도 같다. 문맥에 따른 차이는 이후 Transformer 연산에서 반영된다.

1.3. 위치 인코딩

토큰의 벡터만으로는 문장 안에서 어떤 순서로 놓였는지 알 수 없다. 그래서 위치 정보를 반영한다.

기본 Transformer에서는 토큰 임베딩에 위치 벡터를 더하는 방식을 사용한다.

예시

같은 토큰 벡터라도 놓인 위치에 따라 다른 위치 벡터를 더한다.

토큰 벡터   [0.2, -0.4, 0.7]
위치 벡터 + [0.0,  1.0, 0.0]
최종 입력   [0.2,  0.6, 0.7]

모든 모델이 위치 벡터를 더하는 것은 아니다. 위치 정보를 반영하는 방식은 모델마다 다르다.

위치 인코딩은 순서 정보를 주는 것이고, 문맥에 따른 의미는 Transformer 연산에서 반영된다.

1.4. Transformer 연산

핵심은 두 가지다.

  • Attention: 토큰 사이의 문맥 관계를 반영한다.
  • FFN: 각 토큰의 표현을 가공한다.

이런 블록을 N번 반복한다.

아래 그림은 원래 Transformer의 인코더·디코더 구조다. 왼쪽이 입력을 처리하는 인코더, 오른쪽이 출력을 만드는 디코더다.

모델마다 구성은 다르지만, 여기서는 이 그림을 따라 각 부분의 역할을 살펴본다.

이미지 출처: 카카오페이 기술 블로그에 실린 원본을 그대로 사용했다. 원출처: Vaswani et al., Attention Is All You Need, Figure 1.

1.4.1. 인코딩 — 인코더 레이어

입력 문장의 토큰들이 서로를 참고하도록 해서, 문맥이 반영된 벡터를 만든다.

1.4.1.1. Self-Attention

각 토큰이 같은 입력 안의 다른 토큰을 얼마나 참고할지 계산하고, 그 가중치에 따라 정보를 모은다.

수식으로 쓰면 다음과 같다.

Attention(Q,K,V) = softmax( QKT dk )V

Q·K·V는 입력 토큰 벡터를 서로 다른 학습된 가중치로 변환해 만든 행렬이다. 각각의 역할은 다음처럼 이해했다.

  • Q(Query): 찾을 정보
  • K(Key): 대조할 기준
  • V(Value): 가져올 정보

Kᵀ는 K를 전치한 행렬이고, dₖ는 Q와 K 벡터의 차원 수다.

QKᵀ로 토큰 사이의 관련 점수를 구하고, √dₖ로 나눠 점수의 크기를 조절한다. 각 Query에 대해 Softmax로 참고 가중치를 만든 뒤 V를 곱해 정보를 가중합한다. Attention 수식 원문

예시

세 토큰을 참고하는 가중치가 [0.1, 0.2, 0.7]이면, 각 토큰의 정보 벡터를 0.1 × V₁ + 0.2 × V₂ + 0.7 × V₃으로 모은다. 세 번째 토큰의 정보를 가장 많이 반영하는 셈이다.

1.4.1.2. Multi-Head Attention

Attention 계산을 여러 head에서 수행한 뒤 결과를 합친다. 서로 다른 관계를 반영할 수 있다.

1.4.1.3. Feed-Forward Neural Network

FFN은 Attention을 거친 각 토큰 벡터에 같은 신경망을 적용해 표현을 가공한다. 선형 변환과 비선형 활성화 함수를 사용한다.

토큰 사이의 정보를 모으는 역할은 Attention이 맡고, FFN은 그렇게 만들어진 각 토큰의 표현을 개별적으로 변환한다고 이해했다.

1.4.2. 디코딩 — 디코더 레이어

지금까지 생성한 토큰과 인코더의 출력을 참고해, 다음 토큰을 예측하는 데 쓸 표현을 만든다.

예시

“나는 밥을 먹었다”를 영어로 번역한다면, 인코더는 한국어 입력을 처리한다. 디코더는 이미 생성한 “I”와 인코더 출력을 참고해 “ate” 같은 다음 토큰을 예측한다.

1.4.2.1. Masked Self-Attention

현재 위치보다 뒤에 있는 토큰을 참고하지 못하도록 하는 Self-Attention이다. 각 위치는 자신과 앞의 토큰만 참고한다.

예시

학습 중 [시작 토큰, I, ate]를 입력했더라도, “I” 위치에서 다음 토큰을 예측할 때 뒤의 “ate”를 미리 보면 안 된다. 참고 가능한 위치를 간단히 나타내면 다음과 같다.

현재 위치 시작 토큰 참조 I 참조 ate 참조
시작 토큰 가능 차단 차단
I 가능 가능 차단
ate 가능 가능 가능

차단할 위치의 점수를 Softmax 전에 −∞로 두면, Softmax 뒤의 가중치는 0이 된다.

궁금했던 점

Masked Self-Attention에서 0이 나오면, 뒤의 Attention에서도 이 토큰에 대한 값이 0이 되는 걸까?

0이 되는 것은 미래 토큰을 참고하는 가중치다. 토큰 벡터 전체가 0이 되는 것은 아니다.

1.4.2.2. Cross-Attention

디코더 쪽 표현으로 인코더의 출력을 참고하는 과정이다. 같은 입력 안에서만 계산하는 Self-Attention과 구분된다.

같은 Attention 수식을 사용하되, 디코더 쪽에서 Query를 만들고 인코더 출력에서 Key와 Value를 가져온다.

여기서는 Attention 가중치를 새로 계산한다. 앞의 Masked Self-Attention에서 0이었던 가중치를 그대로 곱해 이어가는 구조는 아니다.

1.4.2.3. Feed-Forward Neural Network

앞선 Attention을 거친 각 토큰 벡터를 개별적으로 가공한다. 동작은 인코더에서 살펴본 FFN과 같다.

1.4.3. 인코더·디코더의 공통 구성

그림의 Add & Norm은 잔차 연결과 Layer Normalization을 뜻한다.

1.4.3.1. 잔차 연결

연산 결과에 기존 입력을 더하는 것이다. x + F(x)처럼 이전 정보를 이어주고, 깊은 신경망의 학습을 돕는다. ResNet을 찾아보며 이해한 부분이다.

1.4.3.2. Layer Normalization

각 토큰 벡터 내부의 값들을 평균과 분산을 기준으로 정규화해 학습을 안정시키는 역할이다. 정규화를 적용하는 위치는 모델마다 다를 수 있다.

1.5. logits 출력

Transformer 블록을 거친 벡터를 출력 선형층에 넣어, 모델의 전체 토큰 목록에 대한 점수를 만든다. 각 점수를 logit, 점수들을 모아 logits라고 한다.

다음 토큰을 생성할 때는 마지막 위치의 logits를 사용한다. 점수가 높을수록 다음 토큰 후보로 더 선호된다는 뜻이며, 아직 확률은 아니다.

logits는 값이 0~1 사이이거나 합이 1일 필요가 없다.

1.6. 확률로 만들기(Softmax)

logits를 Softmax에 넣어 각 토큰의 확률로 바꾼다. 전체 확률의 합은 1이다.

pi= ezi ∑j=1n ezj

zᵢ는 i번째 토큰의 logit, pᵢ는 그 토큰의 확률이고, n은 전체 토큰 종류의 수다. 한 토큰의 exp(logit)을 모든 토큰의 exp(logit) 합으로 나눈다. 여기서 exp(z)는 eᶻ를 뜻한다. Softmax 수식 참고

예시

세 후보의 logits가 [2, 1, 0]이라면, Softmax를 적용했을 때 약 [0.665, 0.245, 0.090]이 된다. 첫 토큰의 확률은 e² / (e² + e¹ + e⁰)으로 계산한다.

1.6.1. Temperature

Temperature는 샘플링할 확률 분포의 뾰족함을 조절하는 매개변수다. T > 0에서 logits를 T로 나눈 뒤 Softmax를 적용한다.

  • T = 1: 원래 Softmax 결과를 사용한다.
  • T > 1: 분포가 평평해져 낮은 점수의 후보도 뽑힐 여지가 커진다. 다양성을 높이는 쪽이다.
  • 0 < T < 1: 높은 점수의 후보에 확률이 더 몰린다. 선택이 보수적으로 바뀌는 쪽이다.

예시

같은 logits [2, 1, 0]이어도 T에 따라 확률이 달라진다.

Temperature 첫 후보 둘째 후보 셋째 후보
T = 0.5 86.7% 11.7% 1.6%
T = 1 66.5% 24.5% 9.0%
T = 2 50.6% 30.7% 18.6%

반올림 때문에 표의 합은 정확히 100%가 아닐 수 있다.

1.7. 샘플링

만들어진 확률을 바탕으로 다음 토큰 하나를 고른다.

1.7.1. Greedy Decoding

확률이 가장 높은 토큰 하나를 고른다.

1.7.2. Random Sampling

확률 분포에 따라 무작위로 하나를 뽑는다. 확률을 기반으로 하는 가챠라고 이해했다.

1.7.3. Top-K Sampling

확률이 높은 K개만 후보로 남긴 뒤, 그 안에서 확률에 따라 하나를 뽑는다.

1.7.4. Top-P Sampling

확률이 높은 순으로 누적 합이 P 이상이 되는 최소 후보 집합을 남긴 뒤, 그 안에서 하나를 뽑는다.

예시

후보가 “먹었다” 50%, “먹는다” 30%, “먹고” 15%, “잔다” 5%라면 다음처럼 달라진다.

방식 이 후보들에 적용하면
Greedy 가장 높은 “먹었다”를 고른다.
Random 네 후보 중 확률에 따라 하나를 뽑는다.
Top-K, K = 2 “먹었다”와 “먹는다”만 남겨 각각 62.5%, 37.5%로 뽑는다.
Top-P, P = 0.9 누적 확률이 95%가 되는 “먹고”까지 세 후보를 남기고, 확률을 다시 맞춰 하나를 뽑는다.

1.8. 디코딩

선택된 토큰 ID들을 토크나이저로 문자열로 복원한다. 1.4절의 디코더 레이어 연산과는 구분되는 과정이다.

예시

선택된 ID가 [30, 31]이고 각각 “ 먹”, “었다”에 해당한다면, 이를 복원해 “ 먹었다”라는 문자열을 얻는다.

생성한 토큰은 다시 입력 뒤에 붙고, 모델은 이어질 다음 토큰을 예측한다.

종료 토큰이 나오거나 설정한 길이에 도달할 때까지 반복하며 문장을 만든다.

2.2. BPE 구현

앞에서는 기존 토크나이저가 문장을 어떻게 나누는지 확인했다. 이번에는 Hugging Face의 BPE 설명을 참고해, 자주 등장하는 토큰 쌍을 찾아 합치는 과정을 직접 구현했다.

구현의 흐름은 다음과 같다.

학습 문서 읽기 → 단어별 등장 횟수 계산 → 문자 단위로 분리
→ 인접한 토큰 쌍의 빈도 계산 → 가장 빈번한 쌍 하나 병합
→ 목표 어휘 크기까지 반복 → 병합 규칙을 새 문장에 적용

빈도 계산과 병합 함수를 먼저 작성하고, 인덱스와 반복문 제어를 고치며 학습 흐름을 연결했다. 데이터 파일 연결, 선택한 쌍만 병합하도록 정리하는 부분, 병합 순서 저장과 새 문장 토큰화 함수, 실행 검증은 AI의 도움을 받았다.

여기서는 문자 기반 BPE를 구현한다. 앞에서 사용한 tiktoken의 byte-level BPE처럼 바이트에서 시작하는 구현과는 시작 단위가 다르다.

2.2.4. 선택한 토큰 쌍 하나만 병합하기

병합 함수는 현재 단어 빈도와 selected_pair를 받는다. 어휘에 있는 토큰을 전부 찾아 합치는 대신, 전달받은 쌍과 정확히 일치하는 위치만 합친다.

#word_frequency 재구성

def symbolic_word_frequency(prev_word_frequency:dict[tuple, int], selected_pair:tuple[str, str]) -> dict[tuple, int]:
    new_word_frequency = {}
    for word, score in prev_word_frequency.items():
        new_words = []
        i = 0
        while True:
            if i >= len(word):
                break

            if i + 1 < len(word) and (word[i], word[i+1]) == selected_pair:
                new_words.append(word[i]+word[i+1])
                i += 2
            else:
                new_words.append(word[i])
                i += 1
        new_word_frequency[tuple(new_words)] = score

    return new_word_frequency

word_frequency

i는 현재 토큰 위치다. 두 토큰이 선택한 쌍과 같으면 합친 토큰을 넣고 두 칸 이동한다. 일치하지 않으면 현재 토큰을 그대로 넣고 한 칸 이동한다. i + 1 < len(word)는 마지막 토큰에서 다음 원소를 읽지 않도록 하는 조건이다.

첫 병합:  aa · a · a
최종 결과: aa · aa

병합에 사용한 토큰을 다시 사용하지 않도록 두 칸씩 이동한다. a · a · a처럼 마지막에 하나가 남으면 aa · a로 보존한다.

여기서 score는 해당 단어의 등장 횟수다. 토큰을 합쳐도 단어가 등장한 횟수는 바뀌지 않으므로 결과 딕셔너리에 그대로 옮긴다. 학습을 시작할 때는 원본 빈도 딕셔너리를 복사해 word_frequency로 사용한다.

2.2.5. 인접한 쌍의 빈도 계산하기

병합할 쌍을 고르기 위해 현재 토큰 튜플을 순회한다. 단어가 여러 번 등장했다면 그 횟수만큼 쌍의 빈도를 더한다.

def score_symbol(word_frequency:dict[tuple, int], symbols:dict):
    scores = {}
    for words, score in word_frequency.items():
        for i in range(len(words)-1):
            pair = (words[i], words[i+1])
            sum_text = words[i] + words[i+1]
            if sum_text in symbols.keys():
                scores[pair] = scores.get(pair, 0) + score
    return scores

scores = score_symbol(word_frequency, symbols)
sorted(scores.items(), key=lambda x: x[1], reverse=True)

pair는 실제로 이웃한 두 토큰이고, sum_text는 둘을 합친 문자열이다. 점수 딕셔너리의 키에는 문자열 대신 pair를 사용했다. ("ab", "c")와 ("a", "bc")는 합친 문자열이 모두 "abc"이지만 서로 다른 병합 규칙이기 때문이다.

빈도를 셀 때는 겹치는 인접 위치도 모두 확인한다. 예를 들어 ("a", "a", "a", "a")가 2번 등장했다면 ("a", "a")의 빈도는 3 × 2 = 6이다. 앞의 병합 함수에서 두 번 합치는 것과는 세는 기준이 다르다.

('a', 'n') 6,559

이 표는 첫 병합 전의 빈도다. 병합할 때마다 점수가 바뀌므로 실제 병합 순서는 이 표의 순위와 달라질 수 있다.

정렬할 때 key=lambda x: x[1]을 넣어 점수 기준으로 비교했다. 이것을 생략하면 (쌍, 점수) 중 앞의 쌍부터 비교하므로 빈도순 정렬이 되지 않는다.

2.2.6. 어휘를 늘리고 병합 순서 저장하기

새 토큰은 기존 어휘에 추가한다. 아래 함수의 길이순 정렬은 어휘를 보기 편하게 나열하기 위한 것이며, 병합 우선순위를 정하는 기준은 아니다.

def update_base_vocab(new:str, base_vocabulary:list):
    new_base_vocabulary = base_vocabulary
    new_base_vocabulary.append(new)
    new_base_vocabulary.sort(reverse=True, key=lambda x: len(x))
    return new_base_vocabulary

new = "".join(sorted(scores.items(), key=lambda x: x[1], reverse=True)[0][0])
update_base_vocab(new, base_vocabulary.copy())

함수 아래의 호출은 첫 후보를 추가해 보는 예시다. .copy()로 어휘의 복사본을 넘겨, 실제 학습 전에 첫 토큰이 미리 추가되지 않게 했다.

이제 쌍의 점수를 계산하고, 가장 빈번한 쌍을 하나 골라 병합하는 과정을 반복한다.

merges = []

while True:
    symbols = make_symbol(base_vocabulary)
    scores = score_symbol(word_frequency, symbols)
    if not scores:
        break
    selected_pair = sorted(scores.items(), key=lambda x: x[1], reverse=True)[0][0]
    new = "".join(selected_pair)
    word_frequency = symbolic_word_frequency(word_frequency, selected_pair)
    merges.append(selected_pair)
    if new not in base_vocabulary:
        base_vocabulary = update_base_vocab(new, base_vocabulary)
    if len(base_vocabulary) >= 800:

한 번 병합할 때마다 인접한 토큰 관계가 바뀌므로 다음 반복에서는 점수를 다시 계산한다. 이때 pre_tokenizer_word_frequency를 매번 넣으면 초기 문자 상태로 돌아가 버린다. 직전 결과인 word_frequency를 다음 병합에 넘겨야 더 긴 토큰으로 이어진다.

scores가 비면 더 병합할 인접 쌍이 없다는 뜻이므로 종료한다. 목표 어휘 크기 800개에 도달한 경우에도 종료한다. 새 토큰은 중복 추가하지 않고, 선택한 쌍은 merges.append(selected_pair)로 기록한다. 빈도가 같을 때는 현재 단어 순회에서 먼저 발견된 쌍을 선택한다.

최종 어휘 목록과 병합 순서는 따로 보관해야 한다. 어휘는 사용 가능한 토큰을 알려주고, merges는 그 토큰들이 어떤 순서로 만들어졌는지 알려준다.

2.2.7. 저장한 규칙으로 새 문장 토큰화하기

새 문장에서는 점수를 다시 계산하거나 병합 규칙을 추가하지 않는다. 학습 때처럼 단어를 나누고 문자 튜플로 만든 다음, merges의 규칙을 처음부터 순서대로 적용한다.

def tokenize(text: str, merges: list) -> list[str]:
    result = []

    for word in text.split(" "):
        if not word:
            continue

        word_state = {tuple(word): 1}

        for pair in merges:
            word_state = symbolic_word_frequency(word_state, pair)

        tokens = list(word_state.keys())[0]
        result.extend(tokens)

    return result

기존 병합 함수를 재사용하기 위해 단어 하나를 {tuple(word): 1} 형태로 넣었다. 여기서 1은 함수의 입력 형식을 맞추기 위한 값이며, 새 문장의 학습 빈도로 쓰이지 않는다.

모든 규칙을 적용한 뒤 딕셔너리의 키를 꺼내면 그 단어의 토큰 튜플을 얻는다. result.extend(tokens)로 토큰을 하나씩 결과 리스트에 붙인다. 문장 전체를 Counter로 묶지 않고 단어를 입력 순서대로 처리하므로, 같은 단어가 반복돼도 빠지지 않는다.

이번에는 문자에서 시작하는 BPE 학습과, 저장한 병합 규칙을 새 문장에 적용하는 부분까지 구현했다. 다음 항목은 포함하지 않았다.

항목 현재 동작

학습에 없던 문자 별도의 [UNK] 처리가 없어 어휘에 없는 문자도 결과에 남을 수 있다.

Byte-level BPE UTF-8 바이트가 아닌 문자에서 시작한다.

따라서 앞의 tiktoken 사이트와 토큰 수가 같아지는 것을 목표로 하지는 않았다. 같은 BPE 원리라도 학습 데이터, 초기 어휘, 사전 토큰화와 병합 규칙이 달라지면 결과도 달라진다.

2.3. 임베딩 결합 구현

토크나이징을 한 각각의 토큰들은 임베딩 과정을 거쳐 고차원의 벡터로 나타낸다. 이 글에선 미리 학습된 GPT-2의 토큰 임베딩과 위치 임베딩을 사용한다.

2.3.1. GPT-2의 토크나이저를 사용하는 이유

앞에서는 BPE의 병합 과정을 이해하기 위해 토크나이저를 직접 구현했다. 임베딩 과정에서는 GPT-2의 토크나이저와 임베딩 테이블을 함께 사용하기로 했다.

GPT-2의 토큰 임베딩 테이블은 50,257개 토큰을 다루지만, 내가 만든 BPE의 어휘는 800개다. 또한 내 구현은 문자를 시작 단위로 삼아 문자열을 합치는 문자 기반 BPE다. GPT-2의 토크나이저는 UTF-8 바이트를 시작 단위로 사용하는 byte-level BPE이므로, 토큰을 구성하는 기준도 다르다.

현재 구현으로 어휘를 50,257개까지 늘리려면 많은 시간이 필요하다. 병합할 때마다 현재 어휘의 모든 토큰 쌍으로 후보를 만들고, 단어들을 순회하며 빈도를 다시 계산하기 때문이다. 어휘가 커질수록 후보를 구성하는 비용도 커진다.

어휘 수를 같게 늘리더라도 같은 ID가 같은 토큰을 가리키는 것은 아니다. 임베딩 테이블의 각 행은 GPT-2의 토큰 ID에 맞춰 학습되어 있으므로, 이번에는 그 테이블과 대응하는 GPT-2 토큰 ID를 그대로 사용한다.

2.3.2. GPT-2의 두 임베딩 표 가져오기

임베딩 표는 토큰마다 벡터 하나를 행으로 저장한 배열이다. 토큰 ID는 이 배열에서 어느 행을 꺼낼지 알려주는 번호이다.

GPT-2의 토큰 임베딩은 wte, 위치 임베딩은 wpe에 저장되어 있다. Hugging Face의 GPT-2 구현에서도 두 표에서 벡터를 조회한 뒤 더한다.

import numpy as np
from transformers import GPT2Tokenizer, GPT2Model

model_name = "openai-community/gpt2"
gpt2_tokenizer = GPT2Tokenizer.from_pretrained(model_name)
gpt2_model = GPT2Model.from_pretrained(model_name)
gpt2_model.eval()

token_embedding_table = (
    gpt2_model.wte.weight.detach().cpu().numpy()
)
position_embedding_table = (
    gpt2_model.wpe.weight.detach().cpu().numpy().copy()
)

모델과 가중치를 불러오는 데는 PyTorch 기반 라이브러리를 사용하고, 가져온 표를 NumPy 배열로 바꿔 이후 계산에 사용한다. 처음 실행할 때는 GPT-2 모델 가중치를 다운로드한다.

가져온 표 크기
토큰 임베딩 wte (50257, 768)
위치 임베딩 wpe (1024, 768)

이 임베딩 테이블에는 50,257개 토큰에 대한 벡터값과 1,024개 위치에 대한 벡터값이 각각 저장되어 있다. 두 표 모두 벡터의 길이가 768이므로 원소끼리 더할 수 있다. 위치 임베딩도 이 모델이 학습한 값을 가져온다.

2.3.3. 문장을 GPT-2 토큰 ID로 변환하기

앞에서 사용한 예제 문장을 GPT-2 토크나이저에 넣는다. encode()의 결과는 문자열 조각이 아닌 정수 ID 목록이다. 이 ID로 토큰 임베딩 테이블을 바로 조회할 수 있다.

new_text = "The European languages are members of the same family."

token_ids = np.array(
    gpt2_tokenizer.encode(new_text, add_special_tokens=False),
    dtype=np.int64,
)
tokens = gpt2_tokenizer.convert_ids_to_tokens(token_ids.tolist())

print("GPT-2 토큰:", tokens)
print("토큰 ID:", token_ids)
print("토큰 수:", len(token_ids))

2.3.4. 위치 벡터를 더해 입력 만들기

토큰 ID로 벡터를 꺼내면 같은 토큰은 어느 위치에 등장해도 같은 벡터를 가져온다. 여기에 문장 안에서의 순서를 반영하기 위해 위치별 벡터를 더한다. 위치 번호는 GPT-2로 나눈 토큰 순서에 따라 0부터 부여한다.

seq_len = len(token_ids)
if seq_len > len(position_embedding_table):
    raise ValueError("위치 임베딩의 최대 길이를 초과했습니다.")

position_ids = np.arange(seq_len)

token_vectors = token_embedding_table[token_ids]
position_vectors = position_embedding_table[position_ids]

x = token_vectors + position_vectors

print("토큰 임베딩 크기:", token_vectors.shape)
print("위치 임베딩 크기:", position_vectors.shape)
print("최종 입력 크기:", x.shape)

핵심 연산은 x[i] = token_embedding_table[token_ids[i]] + position_embedding_table[i]이다. 두 벡터를 이어 붙이는 것이 아니라 같은 차원의 값끼리 더하므로, 벡터의 길이는 768로 유지된다.

3. Self-Attention과 Multi-Head Attention 구현

2.3절에서는 토큰 임베딩과 위치 임베딩을 더해 입력 벡터를 만들었다. 이번에는 각 토큰이 다른 위치를 얼마나 참고할지 정하고, 그 비율로 정보를 섞어 새 벡터를 만드는 과정을 구현했다.

Q·K·V와 가중치의 관계가 헷갈렸는데, 코딩 오페라의 설명을 그림과 함께 읽으며 이해하는 데 도움을 받았다. 아래는 SelfAttention.ipynb와 multiHeadSelfAttention.ipynb의 코드를 바탕으로 정리한 내용이다. 개념 설명과 코드 예시, 실행 검증에는 AI의 도움을 받았다.

Transformer Explainer의 기본 예제에서 Attention을 펼치고 head를 바꾼 화면도 캡처해 넣었다. 사이트는 학습된 GPT-2를 사용한다. 무작위 가중치를 쓴 내 코드와 수치는 다르지만, 각 계산이 무엇을 바꾸는지 볼 수 있다.

  • 3.1. Single-head: 참고 비율로 V 섞기
  • 3.2. Multi-head: 여러 비율로 계산하고 조합하기
  • 3.3. 어텐션 맵으로 Single-head와 Multi-head 비교

3.1. Single-head self-attention 구현

입력 문장은 The European languages are members of the same family.다. GPT-2 토크나이저로 나눈 토큰 10개를 각각 768차원으로 임베딩해, 입력 x의 크기는 (10, 768)이다. 아래 코드는 앞 단계에서 저장한 임베딩을 x로 불러온 상태에서 이어진다.

3.1.1. 같은 입력에서 Q·K·V 만들기

같은 입력에 서로 다른 가중치를 곱해 세 가지 표현을 만든다. Q와 K는 참고할 대상을 비교하는 데, V는 실제 정보를 전달하는 데 사용한다.

Q=XWQ K=XWK V=XWV
구분 기호 · 코드 의미
입력 X · x 토큰·위치 임베딩을 더한 벡터들
가중치 W_Q, W_K, W_V 입력을 각 역할에 맞게 변환하는 행렬
출력 Q · Q 참고할 정보를 찾는 벡터들
출력 K · K Q와 비교할 벡터들
출력 V · V 가져와 섞을 특징 벡터들

그림 출처: Georgia Tech Polo Club, Transformer Explainer. 사이트 제작진이 제공한 설명 그림이다.

그림에서는 Q·K·V를 한 번에 계산해 2304 = 768 × 3차원으로 표시하고 bias도 더한다. 아래 코드는 세 행렬을 나누어 계산하며 bias는 생략했다.

import numpy as np

seq_len, d_model = x.shape
rng = np.random.default_rng(42)
scale = 1 / np.sqrt(d_model)

W_Q = rng.normal(0, scale, size=(d_model, d_model))
W_K = rng.normal(0, scale, size=(d_model, d_model))
W_V = rng.normal(0, scale, size=(d_model, d_model))

Q = x @ W_Q
K = x @ W_K
V = x @ W_V

Q·K·V의 역할은 질문, 답변을 찾기 위한 소개, 실제 답변 내용에 비유해 이해할 수 있다.

Q(Query)는 현재 토큰을 이해하기 위한 질문이다. 어떤 토큰에 대해 “이 토큰이 무엇을 뜻하나요?”라고 질문하는 표현을 만든다고 생각할 수 있다. 토큰의 입력 벡터 x에 W_Q를 곱해 Q로 나타낸다. 여기서 W_Q는 입력을 질문 형식으로 바꾸는 규칙과 비슷하다.

K(Key)는 질문과 비교할 수 있도록 자신이 가진 정보를 소개하는 표현이다. “이 토큰은 ~을 뜻합니다”라는 답변 형식에 비유할 수 있다. 입력 벡터 x에 W_K를 곱해 K를 만든다. W_K는 입력을 질문과 대조할 수 있는 답변 형식으로 바꾸는 규칙과 비슷하다.

V(Value)는 관련 있는 토큰에서 실제로 가져올 내용이다. K가 “내가 이런 정보를 가지고 있습니다”라는 소개라면, V는 “참고할 내용은 이것입니다”라고 전달하는 실제 정보에 해당한다. 입력 벡터 x에 W_V를 곱해, 다른 토큰에 전달하고 섞을 정보를 만든다.

여기서 질문과 답변은 벡터의 역할을 설명하기 위한 비유다. 실제 모델에서 W_Q, W_K, W_V는 학습을 통해 각 역할에 필요한 표현을 만드는 변환 행렬이다. 위 예제에서는 계산 흐름을 확인하기 위해 무작위 값으로 초기화했다.

같은 층의 모든 토큰은 같은 가중치 행렬을 사용한다. Q[0] = x[0] @ W_Q, Q[1] = x[1] @ W_Q처럼 변환 규칙은 같고 입력이 달라 결과도 달라진다. 다른 층은 일반적으로 자신의 가중치를 따로 가진다.

가중치의 크기는 (768, 768), Q·K·V는 각각 (10, 768)이다. @는 행렬곱이다. 같은 위치의 원소끼리 곱하는 *와는 다르다.

3.1.2. Q와 K를 비교해 점수 계산하기

현재 토큰의 질문 q_i와 다른 토큰의 답변 소개 k_j를 내적으로 비교한다. 같은 질문을 기준으로 내적값이 클수록, 모델이 두 표현의 관련성을 높게 평가한 것이다. 질문·답변 비유로 보면 “이 질문에는 어떤 답변이 더 관련 있는가?”를 점수로 나타내는 과정이다. 이를 모든 토큰 쌍에 대해 계산한 결과가 점수 행렬이다.

이 점수를 스케일링하고 mask와 softmax를 적용해 참고 비율을 구한다. 그 비율로 각 토큰의 실제 내용인 V를 가져와 섞는다.

S=QKTdk
구분 기호 · 코드 의미
입력 Q, K 토큰 사이의 관련성을 비교할 벡터들
차원 dₖ · d_k 내적하는 벡터의 길이. 여기서는 768
출력 S · scores 각 토큰이 다른 토큰을 참고할 점수 
scores = Q @ K.T

d_k = Q.shape[-1]
scores = scores / np.sqrt(d_k)

print(scores.shape)  # (10, 10)

K.T는 K의 각 행에 있던 토큰 벡터를 열로 세운다. Q의 각 행과 K의 각 열을 내적하므로 (10, 768) @ (768, 10)의 결과는 (10, 10)이다.

scores[i, j]는 i번째 토큰이 j번째 토큰을 참고할 점수다. 행은 정보를 가져오는 쪽, 열은 정보를 제공하는 쪽으로 읽으면 된다.

내적 차원이 커질수록 점수의 크기도 커지기 쉽다. 이때 softmax가 한쪽에 지나치게 쏠릴 수 있어 sqrt(d_k)로 나눠 크기를 조절한다.

그림 출처: 코딩 오페라, 4-1. Transformer(Self Attention). 설명용 점수이며 이 코드의 실행 결과는 아니다.

그림에서 I 행과 student 열의 1.0은 I가 student를 참고할 점수다. 노란 대각선은 자기 자신과의 점수, 초록색은 두 위치 사이의 점수를 강조한다.

아직 softmax를 적용하지 않았으므로 점수는 확률이 아니다. 이 예시는 대칭이고 대각선 값이 가장 크지만, 실제 Q와 K는 서로 다른 가중치로 만들어져 그런 성질이 보장되지는 않는다.

3.1.3. Causal mask로 미래 위치 차단하기

다음 토큰을 예측할 때는 현재 위치까지의 정보만 사용해야 한다. 현재 위치의 출력으로 그다음 토큰을 예측하므로 자기 자신은 볼 수 있고, 미래 위치는 볼 수 없다.

future_mask = np.triu(
    np.ones((seq_len, seq_len), dtype=bool),
    k=1,
)
masked_scores = np.where(future_mask, -np.inf, scores)

np.triu(..., k=1)은 대각선 바로 위부터 True로 만든다. np.where는 그 위치의 점수를 -inf로 바꾸고 나머지는 유지한다. 앞의 그림에서는 I → student가 차단되고 student → I는 허용된다.

0이 아니라 -inf를 넣는 이유는 다음 softmax 계산에 있다. exp(-inf)는 0이 되지만 exp(0)은 1이다. 점수를 0으로 바꾸는 것만으로는 그 위치를 차단할 수 없다.

3.1.4. Softmax로 참고 비율 구하기

각 행의 점수를 softmax에 넣어 합이 1인 참고 비율로 바꾼다. 수식에서는 허용 위치가 0이고 차단 위치가 −∞인 mask M을 점수에 더한다. 위 코드의 np.where도 같은 효과를 낸다.

A=softmax(S+M)
구분 기호 · 코드 의미
입력 S · scores 토큰 사이의 점수
mask M 허용 위치는 0, 미래 위치는 −∞
출력 A · weights 각 토큰에서 정보를 가져올 비율 
shifted_scores = masked_scores - np.max(
    masked_scores,
    axis=-1,
    keepdims=True,
)
exp_scores = np.exp(shifted_scores)
weights = exp_scores / np.sum(
    exp_scores,
    axis=-1,
    keepdims=True,
)

먼저 각 행의 최댓값을 빼 지수 계산이 너무 커지는 것을 줄인다. 같은 행에서 같은 값을 빼도 최종 softmax 비율은 바뀌지 않는다. 이후 지수 함수를 적용하고, 각 값을 그 행의 합으로 나눈다.

axis=-1은 마지막 축을 따라 계산한다는 뜻이다. 여기서는 한 Query가 참고할 Key들의 점수를 대상으로 한다. keepdims=True는 행별 최댓값과 합을 (10, 1)로 유지한다. 덕분에 (10, 10) 배열의 각 행에 맞춰 빼거나 나눌 수 있다.

예시

토큰 세 개에 대한 가상 점수 한 행을 계산하면 다음과 같다. 값은 소수점 넷째 자리까지 반올림했다.

점수             [2,      1,     -inf]
최댓값 빼기      [0,     -1,     -inf]
지수 함수 적용   [1,      0.3679, 0   ]
행의 합으로 나눔 [0.7311, 0.2689, 0   ]

첫 번째 토큰을 약 73.1%, 두 번째 토큰을 약 26.9% 참고한다. 차단된 세 번째 위치의 비율은 0이다.

실제 입력에서 세 번째 토큰의 비율 weights[2]는 다음과 같았다.

[0.3296048  0.33390219 0.33649301 0. 0. 0. 0. 0. 0. 0.]

앞의 두 토큰과 자기 자신에게만 비율이 배정됐다. 미래 위치는 모두 0이고, weights.sum(axis=-1)로 확인한 각 행의 합은 약 1이었다.

화면 출처: Transformer Explainer. AI 도구로 기본 예제의 Attention을 펼쳐 캡처했다. 내 NumPy 코드의 실행 결과는 아니다.

세 행렬을 왼쪽부터 보면 코드의 흐름과 같다. Dot product는 Q·K의 내적 점수다. Scaling · Mask에서는 점수 크기를 조절하고 오른쪽 위의 미래 위치를 차단한다. Softmax는 이를 0~1의 참고 비율로 바꾼다. 이 head는 여러 행에서 첫 번째 토큰을 많이 참고한다.

3.1.5. 비율로 V를 섞어 새 벡터 만들기

처음에는 weights에 이미 문맥이 반영되어 있는데 왜 V를 곱하는지 헷갈렸다. weights에는 참고 비율이, V에는 그 비율을 적용할 특징값이 들어 있다.

Z=AV zi=∑j=1TAijvj
구분 기호 · 코드 의미
입력 A · weights 토큰별 참고 비율. 한 행에 10개
입력 V · V 토큰별 특징 벡터. 한 행에 768개 성분
출력 Z · context 비율에 따라 특징을 섞은 토큰별 새 벡터

아래쪽 식은 i번째 출력 하나를 풀어 쓴 것이다. T는 토큰 수이며, 각 토큰의 V에 그 토큰을 참고할 비율을 곱해 더한다.

context = weights @ V
print(context.shape)  # (10, 768)

위에서 구한 세 번째 토큰의 비율을 적용하면 다음 세 항만 남는다. 미래 위치의 비율은 0이므로 결과에 영향을 주지 않는다.

context[2] ≈ 0.3296048  × V[0]
           + 0.33390219 × V[1]
           + 0.33649301 × V[2]

weights @ V는 이 가중합을 모든 토큰에 대해 한꺼번에 계산한다. 새로운 참고 비율을 정하는 것이 아니라, Q와 K로 정한 비율을 V의 특징값에 적용하는 것이다.

비율은 벡터 일부를 고르는 것이 아니라 전체 벡터의 기여량을 조절한다. 25%를 참고한다면 해당 V의 768개 성분 모두에 0.25를 곱한다.

K와 V를 따로 만드는 이유는 비교할 특징과 전달할 특징을 각각 학습하기 위해서다. W_K는 관련성을 비교할 표현을, W_V는 다른 토큰에 전달할 표현을 만든다.

3.2. Multi-head self-attention 구현

Single-head에서는 한 토큰의 참고 비율을 V의 768개 성분 전체에 적용했다. Multi-head는 같은 입력에서 여러 특징 묶음을 만들고 묶음마다 별도의 참고 비율을 계산한다. 어떤 묶음은 한 토큰을, 다른 묶음은 다른 토큰을 더 많이 반영할 수 있다.

각 head의 역할을 미리 지정하지는 않는다. 어떤 관계와 특징을 사용할지는 학습으로 정해진다.

3.2.1. Q·K·V를 head별로 나누기

앞에서 만든 (10, 768) 크기의 Q·K·V를 사용한다. Head 수를 12개로 정하면 head 하나의 차원은 768 / 12 = 64다. 토큰 수가 아니라, 변환된 Q·K·V의 특징 차원을 나눈다.

num_heads = 12
assert d_model % num_heads == 0
d_head = d_model // num_heads

Q_heads = Q.reshape(seq_len, num_heads, d_head)
print(Q_heads.shape)  # (10, 12, 64)

현재 축 순서는 (토큰, head, 성분)이다. Q_heads[0, 0]은 첫 번째 토큰의 첫 번째 head Q이고, Q_heads[0, 1]은 같은 토큰의 두 번째 head Q다.

Head별로 계산하기 편하도록 head 축을 앞으로 옮긴다. K와 V에도 같은 변환을 적용한다.

Q_heads = Q_heads.transpose(1, 0, 2)
K_heads = K.reshape(seq_len, num_heads, d_head).transpose(1, 0, 2)
V_heads = V.reshape(seq_len, num_heads, d_head).transpose(1, 0, 2)

print(Q_heads.shape)  # (12, 10, 64)

이제 축 순서는 (head, 토큰, 성분)이다. Q_heads[0]에는 첫 번째 head가 사용할 토큰 10개의 Q가 (10, 64) 배열로 들어 있다. 모든 head가 모든 토큰을 대상으로 계산한다.

Head별 가중치는 큰 W_Q의 출력 열에 나뉘어 있다. W_Q[:, :64]는 첫 번째 head, W_Q[:, 64:128]은 두 번째 head에 해당한다. 따라서 Q_heads[0]은 x @ W_Q[:, :64]와 같다.

각 head는 입력의 768개 성분 전체를 보고 자기 64차원 표현을 만든다. 입력 x를 64개씩 잘라 쓰는 구조가 아니다. K와 V도 같은 방식이다.

3.2.2. Head마다 점수와 참고 비율 계산하기

Single-head와 같은 계산을 12개 head에 대해 수행한다.

head_scores = Q_heads @ K_heads.swapaxes(-1, -2)
head_scores = head_scores / np.sqrt(d_head)

print(head_scores.shape)  # (12, 10, 10)

swapaxes(-1, -2)는 K의 마지막 두 축만 바꾼다. (12, 10, 64)가 (12, 64, 10)이 되어 각 head 안에서 행렬곱을 수행할 수 있다. 3차원 배열에 .T를 쓰면 모든 축 순서가 뒤집히므로 여기서는 사용하지 않는다.

head_scores[h, i, j]는 h번째 head에서 i번째 토큰이 j번째 토큰을 참고할 점수다. 내적 차원도 head 하나의 길이인 64를 사용한다.

같은 (10, 10) mask를 모든 head에 적용하고, 마지막 축으로 softmax를 계산한다.

head_masked_scores = np.where(future_mask, -np.inf, head_scores)
shifted_scores = head_masked_scores - np.max(
    head_masked_scores,
    axis=-1,
    keepdims=True,
)
exp_scores = np.exp(shifted_scores)
head_weights = exp_scores / np.sum(
    exp_scores,
    axis=-1,
    keepdims=True,
)

print(head_weights.shape)  # (12, 10, 10)

Mask는 broadcasting으로 12개 head에 각각 적용된다. 각 head의 각 행은 합이 1인 참고 비율이다. Single-head의 (10, 10) 행렬이 이제 head별로 하나씩 생긴 것이다.

3.2.3. 각 head의 비율로 V 섞기

head_context = head_weights @ V_heads
print(head_context.shape)  # (12, 10, 64)

각 head가 자기 참고 비율로 자기 V를 가중합한다. 이때 해당 head의 V에 있는 64개 성분 전체에 같은 비율을 적용한다. 다른 head는 자신의 Q·K로 계산한 다른 비율을 사용할 수 있다.

결과적으로 같은 토큰에 대해 head별로 64차원 벡터가 하나씩 만들어진다.

같은 기본 예제에서 Head 2로 바꾸고 Attention을 펼쳐 캡처했다. 화면 출처: Transformer Explainer.

앞의 Head 1과 달리 Head 2의 Softmax는 대각선이 진하다. 자기 위치를 많이 참고한다는 뜻이다. 같은 입력이어도 head마다 참고 비율이 다르다. 아래쪽 초록색 Value가 보라색 Out으로 이어지는 흐름은 그 비율로 V를 섞는 head_weights @ V_heads에 대응한다.

3.2.4. 같은 토큰의 head 결과끼리 이어 붙이기

현재 배열은 (head, 토큰, 성분) 순서다. 같은 토큰의 결과끼리 모이도록 토큰 축을 앞으로 옮긴 뒤 마지막 두 축을 합친다.

merged_context = head_context.transpose(1, 0, 2)
print(merged_context.shape)  # (10, 12, 64)

merged_context = merged_context.reshape(seq_len, d_model)
print(merged_context.shape)  # (10, 768)

토큰 하나의 벡터는 [head 1의 64개 | head 2의 64개 | ... | head 12의 64개]로 이어진다. transpose 후 reshape 순서를 지켜야 서로 다른 토큰의 결과가 섞이지 않는다.

3.2.5. W_O로 head들의 특징 조합하기

Head 결과를 합쳤으니 끝난 것 아닌가 싶었는데, 이어 붙이기는 결과를 나란히 놓는 연산이다. W_O는 여러 head가 만든 성분을 어떻게 조합할지 학습하는 행렬이다.

C=Concat(Z1,…,ZH) Y=CWO
구분 기호 · 코드 의미
입력 Z₁ … Z_H · head_context H개 head가 만든 결과. 여기서는 H = 12
중간 결과 C · merged_context 같은 토큰의 head 결과를 이어 붙인 벡터
가중치 W_O · W_O head들의 특징을 조합하는 행렬
출력 Y · output 특징을 조합한 최종 토큰 벡터들 
W_O = rng.normal(0, 1 / np.sqrt(d_model), size=(d_model, d_model))
output = merged_context @ W_O

print(output.shape)  # (10, 768)

예시

Head 두 개의 결과가 각각 [2], [5]라고 가정하면, 이어 붙인 값은 [2, 5]다. 여기에 아래 행렬을 곱하면 두 head의 값을 더하거나 빼서 새 특징을 만든다.

np.array([2, 5]) @ np.array([[1, 1], [1, -1]])  # [7, -3]

설명용 숫자이며 노트북의 실제 출력은 아니다.

head_weights는 토큰 사이의 정보를 섞고, W_O는 head들이 만든 특징 성분을 섞는다. W_O는 참고 확률이 아니므로 음수도 가능하고 합이 1일 필요도 없다. 다른 가중치처럼 한 번 초기화하고 같은 층의 모든 토큰과 다음 입력에 재사용한다.

3.2.6. 실행 결과

코드를 처음부터 실행했을 때 배열 크기는 다음과 같았다.

단계 크기 각 축의 의미
Q, K, V 각각 (10, 768) 토큰, 전체 특징
head별 Q, K, V 각각 (12, 10, 64) head, 토큰, head의 특징
head별 점수와 참고 비율 (12, 10, 10) head, 참고하는 토큰, 참고할 토큰

Head별 참고 비율의 행 합은 약 1이고 미래 위치의 비율은 0이었다. 최종 출력에는 NaN이나 무한대가 없었다. 입력과 출력의 크기는 같지만, 출력은 다른 토큰의 정보를 반영한 새 표현이다.

이 단계에서는 Attention까지 구현했다. Transformer 블록을 구성할 LayerNorm·잔차 연결·FFN과 다음 토큰 점수를 만드는 어휘 출력층은 4장에서 이어서 연결한다.

3.3. 어텐션 맵으로 Single-head와 Multi-head 비교

AttentionMapComparison.ipynb에서 같은 x, W_Q, W_K, W_V로 계산한 참고 비율을 비교했다. 비교 코드와 시각화는 AI의 도움을 받아 작성했다.

왼쪽은 Single-head, 가운데와 오른쪽은 Multi-head의 Head 1·2다. 행은 현재 토큰, 열은 참고할 토큰이며, 진한 파란색일수록 참고 비율이 높다. 회색은 차단된 미래 위치다.

Single-head는 768차원 전체로 하나의 참고 비율 맵을 만든다. Multi-head는 64차원씩 나눠 head마다 따로 계산하므로, 같은 입력과 가중치라도 참고 비율이 달라진다.

현재 가중치는 랜덤값이라, 이 차이를 학습된 의미 관계로 해석할 수는 없다. family가 members를 많이 참고해야 하는 것도 아니다. 추후에는 GPT-2의 학습된 가중치를 적용해 어텐션 맵을 비교해볼 계획이다.

4. Transformer 블록과 전체 순전파 구현

3장에서는 Multi-Head Masked Self-Attention까지 구현했다. 전체 순전파를 조립하기 전에, 블록을 구성하는 나머지 연산인 LayerNorm, 잔차 연결, FFN의 원리와 코드를 정리한다.

4.1. LayerNorm

LayerNorm은 입력을 정규화하기 위해 사용한다. 입력 x의 크기가 (seq_len, 768)이라면, 토큰 하나를 나타내는 각 행의 768개 성분 안에서 평균과 분산을 계산한다.

x^i=xi−μσ2+ϵ

μ는 해당 토큰 벡터의 평균, σ²는 분산이다. 평균을 빼서 중심을 0으로 옮기고, 표준편차로 나눠 값이 퍼진 정도를 조절한다. ϵ는 분산이 0이거나 아주 작을 때도 나눗셈을 안정적으로 계산하기 위한 작은 값이다.

이렇게 하면 벡터의 전체적인 크기와 평균을 정돈해, 다음 층이 입력 스케일의 변화에 지나치게 영향받지 않도록 돕는다. 다른 토큰과 평균을 내는 연산은 아니다.

GPT-2의 LayerNorm은 여기서 끝나지 않고, 정규화한 값에 학습 가능한 γ를 곱하고 β를 더한다.

LayerNorm(x)i=γix^i+βi

γ와 β의 크기는 각각 (768,)이고, 같은 LayerNorm을 지나는 모든 토큰이 공유한다. 평균과 분산은 입력마다 다시 계산하지만, γ와 β는 학습 파라미터다. 따라서 최종 출력의 평균과 분산이 항상 0과 1인 것은 아니다.

import numpy as np

def layer_norm(x, gamma, beta, eps=1e-5):
    mean = np.mean(x, axis=-1, keepdims=True)
    var = np.var(x, axis=-1, keepdims=True)

    normalized = (x - mean) / np.sqrt(var + eps)
    return gamma * normalized + beta


# x: 앞 단계에서 만든 (seq_len, d_model) 입력
d_model = x.shape[-1]
gamma_1 = np.ones(d_model)
beta_1 = np.zeros(d_model)

x_norm = layer_norm(x, gamma_1, beta_1)

axis=-1로 마지막 차원인 벡터 성분 방향을 계산한다. keepdims=True를 쓰면 평균과 분산의 크기가 (seq_len, 1)로 유지돼 각 행에 맞춰 뺄셈과 나눗셈이 적용된다. np.var는 기본값인 ddof=0을 사용한다.

4.2. 잔차연결

y=x+F(x)

잔차 연결은 계산 결과 F(x)와 원래 입력 x를 더하는 것이다. 입력을 그대로 전달하는 것이 유리한 상황에서도, 매번 새로운 변환만 거치게 되면 필요한 표현이 달라질 수 있다. 잔차 연결은 입력이 직접 전달되는 경로를 두고, 그 위에 계산한 변화를 더하도록 한다.

F(x)가 0에 가까우면 입력이 거의 그대로 전달된다. 다만 원래 입력이 별도로 저장되는 것은 아니며, 더한 결과도 입력과 달라질 수 있다.

예시

사진의 밝기만 조금 높이는 상황에 비유할 수 있다.

  • 잔차 연결 없음: 모델이 보정된 사진 전체를 만들어야 하므로, 밝기를 바꾸려다 원래 모습까지 달라질 수 있다.
  • 잔차 연결 있음: 원본 사진을 직접 전달하고 밝기 보정량만 더하도록 학습할 수 있다.

GPT-2에서는 LayerNorm을 거친 입력으로 Attention을 계산하고, 그 결과를 정규화하기 전의 입력 x에 더한다.

h=x+Attention(LayerNorm1(x)) 
# output: x_norm으로 Q, K, V부터 계산한 어텐션 출력
# x는 정규화하기 전의 입력으로 유지한다.
assert x.shape == output.shape
h = x + output

입력과 출력 크기를 확인하는 것은 NumPy의 브로드캐스팅으로 의도와 다른 덧셈이 일어나는 것을 막기 위해서다. 잔차 연결 자체에는 별도의 학습 파라미터가 없다.

입력에서 출력으로 직접 이어지는 경로는 역전파 때 기울기가 전달될 경로도 제공하므로, 깊은 모델의 학습을 돕는다.

4.3. FFN

FFN은 토큰 벡터의 성분들을 조합하고 비선형적으로 변환한다. Attention이 토큰 사이에서 정보를 가져왔다면, FFN은 그 정보가 반영된 각 토큰 벡터를 가공한다. 모든 토큰에 같은 가중치를 적용하지만, FFN 내부에서 토큰끼리 직접 정보를 섞지는 않는다.

FFN(z)=GELU(zW1+b1)W2+b2

여기서 z는 두 번째 LayerNorm을 통과한 FFN 입력이다. GPT-2 small을 기준으로 계산 순서와 차원은 다음과 같다.

z=LayerNorm2(h)

앞선 잔차 연결의 결과 h를 정규화해 FFN의 입력 z를 만든다.

a=zW1+b1

가중치 W₁과 편향 b₁로 입력 성분을 조합해, 768차원을 3072차원으로 넓힌다.

u=GELU(a)

각 성분에 GELU를 적용해 비선형으로 변환한다. 차원은 3072로 유지된다.

FFN(z)=uW2+b2

가중치 W₂와 편향 b₂로 중간 특징을 다시 조합해, 원래의 768차원으로 돌려놓는다.

단계 벡터 크기 하는 일
입력 z (seq_len, 768) 토큰별 입력 벡터
첫 번째 선형 변환 a (seq_len, 3072) 성분들을 조합해 차원 확장
GELU 적용 u (seq_len, 3072) 비선형 변환
두 번째 선형 변환 (seq_len, 768) 원래 차원으로 변환

3072차원으로 늘리는 것은 입력을 네 번 복사하는 것이 아니다. 서로 다른 가중치로 입력 성분을 조합해 더 많은 중간 특징을 만들고, 마지막 변환에서 다시 768차원으로 모은다.

중간에 적용하는 GELU의 GPT-2 근사식은 다음과 같다.

GELU(t)≈t2[1+tanh(2π(t+0.044715t3))]

GELU는 큰 양수는 거의 그대로 통과시키고, 큰 음수는 0에 가깝게 만든다. 0 근처에서는 부드럽게 변하며, 음수를 모두 정확히 0으로 만드는 함수는 아니다.

이 함수를 중간에 넣는 이유는 선형 변환만 반복하면 하나의 선형 변환으로 합쳐지기 때문이다.

(zW1)W2=z(W1W2)

편향이 있어도 하나의 선형 변환과 편향으로 묶을 수 있다. GELU로 비선형성을 추가해야 입력에 따라 달라지는 더 복잡한 변환을 표현할 수 있다.

def gelu(x):
    return 0.5 * x * (
        1 + np.tanh(
            np.sqrt(2 / np.pi) * (x + 0.044715 * x**3)
        )
    )


d_model = h.shape[-1]
d_ff = 4 * d_model
rng = np.random.default_rng(42)

W_1 = rng.normal(0, 0.02, size=(d_model, d_ff))
b_1 = np.zeros(d_ff)
W_2 = rng.normal(0, 0.02, size=(d_ff, d_model))
b_2 = np.zeros(d_model)

# 두 번째 LayerNorm은 별도의 gamma, beta를 사용한다.
gamma_2 = np.ones(d_model)
beta_2 = np.zeros(d_model)
h_norm = layer_norm(h, gamma_2, beta_2)

ffn_hidden = h_norm @ W_1 + b_1
ffn_activated = gelu(ffn_hidden)
ffn_output = ffn_activated @ W_2 + b_2

# FFN 결과도 정규화하기 전의 입력에 더한다.
assert h.shape == ffn_output.shape
y = h + ffn_output

코드의 FFN 가중치는 학습 전의 무작위 값이다. h → 두 번째 LayerNorm → FFN으로 계산한 결과를 다시 h에 더하면 블록의 두 번째 잔차 연결까지 이어진다.

4.4. 결합

이제 앞에서 만든 연산을 연결할 차례다. GPT-2의 구조를 정하는 설정은 Hugging Face의 config.json에 있었다. 여기서는 이 저장소의 GPT-2 small을 기준으로 조립한다.

4.4.1. GPT-2의 헤드 구조

설정의 n_embd는 768, n_head는 12다. 따라서 Q·K·V를 각각 12개의 헤드로 나누면, 헤드 하나가 다루는 차원은 768 / 12 = 64가 된다.

각 헤드가 계산한 결과는 이어 붙여 다시 768차원으로 만든다. 이 과정은 3.2절의 Multi-head self-attention 구현에서 정리했다.

4.4.2. GPT-2의 블록 구조

블록 내부의 연산 순서는 GPT-2 원본 구현의 block()에서 확인했다. GPT-2는 Attention과 FFN 앞에 LayerNorm을 적용하며, 각 계산 결과에 정규화하기 전의 입력을 더한다.

입력 x
  ↓
LayerNorm ①
  ↓
Masked Multi-Head Attention
  ↓
원래 입력 x와 더하기 → h
  ↓
LayerNorm ②
  ↓
FFN: 768 → 3072 → GELU → 768
  ↓
FFN에 들어가기 전의 h와 더하기 → 블록 출력

토큰 수가 seq_len이라면 블록의 입력과 출력은 모두 (seq_len, 768)이다. FFN에서 중간 차원을 넓혔다가 다시 768차원으로 돌려놓기 때문에 잔차 연결을 이어갈 수 있다.

4.4.3. GPT-2의 블록 개수

n_layer는 12다. 위 구조의 블록을 12개 쌓고, 앞 블록의 출력을 다음 블록의 입력으로 전달한다. 블록의 계산 구조는 같지만 가중치는 블록마다 따로 가진다.

즉, 12개 블록 각각의 Attention 안에 12개 헤드가 있다.

4.4.4. 전체적인 구조

토큰 임베딩과 위치 임베딩을 더한 입력에서 시작해, 12개 블록을 통과한 뒤 마지막 LayerNorm과 어휘 출력층을 연결한다.

토큰 ID
  ↓
토큰 임베딩 + 위치 임베딩
  ↓
Transformer 블록 × 12
  ↓
마지막 LayerNorm
  ↓
토큰 임베딩 표의 전치와 곱하기
  ↓
logits: (seq_len, 50257)
  ↓
Softmax → 다음 토큰의 확률

출력층은 입력에 사용한 토큰 임베딩 표를 공유한다. 각 위치의 logits은 그 위치 다음에 올 토큰의 점수다. 전체 흐름은 원본 구현의 model()에서도 확인할 수 있다.

5. 공개 가중치 적용과 Hugging Face 비교, 샘플링

4장에서 GPT-2의 계산 과정을 연결했다. 이번에는 공개 GPT-2 가중치를 적용하고, Hugging Face(HF) 모델과 출력이 얼마나 같은지 비교했다.

먼저 어느 함수에 어떤 가중치를 넣는지, 그 가중치를 원본 파일 어디에서 가져오는지 정리한다. 이어서 실제 logits와 오차를 확인하고, 같은 가중치인데도 차이가 생긴 이유를 살펴본다.

5.1. 가중치가 필요한 곳

@는 행렬 곱셈, W는 입력에 곱하는 행렬, b는 결과에 더하는 편향(bias) 벡터다. W와 b 모두 학습된 값을 파일에서 가져온다.

5.1.1. 임베딩 — forward()

토큰 ID와 위치를 벡터로 바꾸는 표가 필요하다. wte는 토큰 임베딩 표, wpe는 위치 임베딩 표다.

입력 벡터 = wte[토큰 ID] + wpe[위치]

5.1.2. LayerNorm — layer_norm()

정규화한 벡터에 곱할 gamma와 더할 beta가 필요하다.

정규화된 x = (x - 평균) / √(분산 + ε)
출력 = gamma × 정규화된 x + beta

평균·분산은 입력에서 계산하고, ε는 나눗셈을 안정화하는 작은 상수다. 파일에서는 gamma, beta를 가져와 성분별로 적용한다.

5.1.3. Attention — multi_head_self_attention()

Q·K·V를 만들 때와 헤드를 합친 결과를 변환할 때 각각 W, b가 필요하다. x는 첫 LayerNorm을 통과한 입력이다.

Q = x @ W_Q + b_Q
K = x @ W_K + b_K
V = x @ W_V + b_V

출력 = 헤드를 합친 결과 @ W_O + b_O

어텐션 확률은 입력마다 계산하고, W, b는 파일에서 가져온다. Q·K·V로 확률을 구하는 과정은 Attention 글에서 다뤘다.

5.1.4. FFN — feed_forward()

벡터를 넓히는 W_1, b_1과 줄이는 W_2, b_2가 필요하다. x는 두 번째 LayerNorm을 통과한 입력이다.

중간값 = GELU(x @ W_1 + b_1)
출력 = 중간값 @ W_2 + b_2

GPT-2에서는 768 → 3072 → 768차원으로 계산한다. GELU 자체에는 가져올 가중치가 없다.

5.1.5. 블록 연결 — forward()의 블록 반복

위의 LayerNorm·Attention·FFN을 순서대로 실행하고 잔차를 더한다.

h = x + Attention(LayerNorm_1(x))
출력 = h + FFN(LayerNorm_2(h))

각 함수의 가중치를 그대로 사용하며, 잔차를 더하는 데는 별도 가중치가 없다.

5.1.6. 최종 출력 — forward()

마지막 LayerNorm의 gamma, beta를 적용한 뒤, 입력에서 썼던 wte를 다시 사용한다.

마지막 벡터 = LayerNorm_f(마지막 블록의 출력)
logits = 마지막 벡터 @ wte.T
확률 = softmax(logits)

wte.T는 wte의 행과 열을 바꾼 것이다. 출력층은 입력 임베딩을 공유하며, softmax에는 별도 가중치가 없다.

logits는 다음에 올 토큰 후보마다 매긴 점수다. 점수가 높을수록 모델이 더 유력하게 보는 후보이며, softmax를 적용하면 후보별 확률이 된다.

5.6. 같은 가중치인데 왜 차이가 났을까?

내 코드에서는 Attention 점수를 나누는 부분을 원래대로 유지했다.

head_scores = head_scores / np.sqrt(d_head)

현재 사용한 NumPy 2.5.4에서는 np.sqrt(d_head)가 float64 값을 만들고, 이 나눗셈부터 중간값도 float64가 된다. HF 모델은 float32로 계산했으므로, 기본 비교에서는 두 모델의 계산 정밀도가 달랐다.

float32와 float64는 중간값을 저장할 수 있는 정밀도가 달라, 계산 중 반올림 결과도 달라질 수 있다.

설명용 예시: 정밀도에 따른 반올림

계산: (100,000,000 + 1) - 100,000,000

float32 결과: 0
float64 결과: 1

float32는 이 크기에서 +1의 차이를 저장하지 못해 중간값이 반올림된다.

모델에서도 작은 차이가 이후 층의 계산에 영향을 줄 수 있다. float32 가중치를 float64로 바꿔도 가중치 값 자체는 유지되고, 이후 계산을 수행하는 정밀도가 달라진다.

중간 출력을 보니 임베딩은 정확히 같았고, 첫 블록부터 차이가 생겼다. 차이가 컸던 두 입력을 양쪽 모두 float64로 다시 계산했다.

다시 비교한 입력 기존 계산의 최대오차 양쪽 모두 float64일 때
자연문 256토큰 0.00792682 약 1.17 × 10⁻¹¹
0 128회 반복 0.00264310 약 2.59 × 10⁻¹²

두 입력 모두 차이가 크게 줄었다. HF 모델 자체도 같은 자연문 입력에서 float32와 float64 결과 사이에 최대 약 0.00749의 차이가 있었다.

이 재실험은 계산 정밀도가 오차의 주요 요인임을 뒷받침한다. 다만 float64 재실험은 두 입력만 확인한 결과다.

방식 비교한 설정
Greedy 점수가 가장 높은 토큰 선택
온도만 조절 T=0.1·1.0·2.0, 후보 제한 없음

6.2.3. 스케일링의 역할과 탐구 질문

질문: Q와 K의 내적을 왜 √dₖ로 나눌까?

6.4.3. 잔차 연결의 역할과 탐구 질문

질문: Attention과 FFN의 출력에 왜 입력을 다시 더할까?

Attention 출력은 여러 위치의 V를 참고 비율로 섞고 변환한 값이다. 이 값만 다음 단계로 넘기면 현재 토큰의 벡터를 섞인 정보로 대체하게 된다. 비슷한 위치를 비슷한 비율로 참고하는 토큰들은 출력도 비슷해질 수 있어, 원래 토큰을 구분하던 특징이 약해질 수 있다.

x + attention은 원래 토큰의 벡터를 직접 전달하는 경로를 두고, 그 위에 참고한 정보를 더한다. 입력 정보가 Attention 출력에도 반영되지만, 잔차 연결이 없으면 그 정보가 모두 Attention의 변환을 거쳐야 한다.

GPT-2의 가중치는 잔차 연결이 있는 상태로 학습됐다. 가중치를 유지한 채 이 경로를 빼자 다음 토큰 분포가 크게 달라졌다. 이 입력의 결과만으로 잔차 제거가 항상 가장 큰 영향을 준다고 볼 수는 없다.

여기까지는 가중치를 고정하고 구성 요소를 바꿨다. 이어서는 손실을 계산하고 학습에 사용하는 원리를 살펴본다. 각 항목은 역할, 수식, 짧은 설명, 숫자 예시 순서로 정리했다.

SFT·RLHF·DPO의 숫자는 설명용 가상 예제다. 로그는 자연로그이며 수치는 반올림해 표시했다. 실제 GPT-2를 미세조정한 결과는 아니다.

6.5. 다음 토큰 예측 손실

다음 토큰 예측 손실은 모델이 실제 정답 토큰에 얼마나 높은 확률을 줬는지 평가하는 값이다.

L=−1N∑t=1Nln(pt)
  1. pt는 각 위치의 정답 토큰 확률이다. 여기에 −ln을 취하면 정답 확률이 낮을수록 손실이 커진다.
  2. ∑로 위치별 손실을 더하고, 토큰 수 N으로 나눠 평균을 구한다. 정답이 one-hot일 때의 교차 엔트로피와 같은 계산이다.

예시 · 두 토큰의 평균 손실

답변을 [서울] [입니다] 두 토큰으로 가정하고, 각 정답 확률이 0.5와 0.25라고 하자. 실제 GPT-2 토큰화 결과는 아니다.

L1=−ln(0.5)≈0.693147

서울에 준 확률 0.5를 첫 번째 위치의 손실로 바꾼 값이다.

L2=−ln(0.25)≈1.386294

입니다에는 더 낮은 확률을 줬으므로 손실이 더 크다.

L=0.693147+1.3862942≈1.039721

두 손실을 더하고 토큰 수 2로 나눈 토큰당 평균 손실이다.

같은 계산을 기존 GPT-2의 Hello! My Name Is 출력에도 적용했다. 네 개의 실제 다음 토큰 !, My, Name, Is를 정답으로 평가한 평균 손실은 3.587852였다.

6.6. SFT: 모범 답변을 따라 배우기

SFT는 질문과 모범 답변을 주고, 그 답변이 나오도록 모델을 추가 학습하는 것이다.

LSFT=−∑tmtln(pt)∑tmt
  1. pt는 정답 토큰 확률, mt는 손실에 포함할 위치의 마스크다. 여기서는 답변에 1, 프롬프트에 0을 둔다.
  2. 마스크를 곱한 손실을 더하고, 포함한 답변 토큰 수로 나눈다. 앞선 문맥에는 실제 모범 답변 토큰을 넣는다.

예시 · 마스크로 답변 손실만 남기기

질문과 답변을 [대한민국의] [수도는?] [서울] [입니다]로 단순화해 보자. 마스크는 입력 토큰이 아니라 예측할 정답을 기준으로 붙인다.

예측할 정답 정답 확률 pt 마스크 mt
수도는? — 질문 내부 0.3 0
서울 — 답변 0.5 1
입니다 — 답변 0.25 1
0×(−ln(0.3))=0

질문 내부 토큰은 마스크가 0이므로, 그 위치의 손실이 합계에서 빠진다.

손실 합=−ln(0.5)−ln(0.25)≈2.079442

답변 두 위치는 마스크가 1이어서 손실이 그대로 남는다.

LSFT≈2.0794420+1+1=1.039721

분모는 전체 예측 위치 3개가 아니라 포함한 답변 토큰 2개다. 프롬프트 마지막 위치에서 첫 답변을 예측하는 손실도 포함한다.

6.7. RLHF: 사람이 선호한 답변을 더 자주 만들기

RLHF는 사람의 피드백을 보상으로 연결해 언어 모델을 학습하는 것이다. 여기서는 보상 모델을 학습한 뒤 PPO를 사용하는 대표적인 흐름을 다룬다.

계산은 보상 모델 → 기대 보상·KL → Advantage → PPO·가치 모델 순서로 이어진다.

6.7.1. 보상 모델 손실

보상 모델 손실은 사람이 고른 답변에 상대적으로 높은 점수를 주도록 학습하는 기준이다.

LRM=−lnσ(rA−rB)
σ(z)=11+e−z
  1. 선호 답변의 점수 rA에서 비선호 답변의 점수 rB를 뺀다.
  2. sigmoid σ는 점수 차이 z를 0~1의 선호 확률로 바꾼다. 식의 e는 약 2.718이다.
  3. 선호 확률에 음의 로그를 취한다. 이 손실로 보상 모델을 학습한다.

예시 · 보상 점수에서 선호 확률로

사람은 A를 골랐고, 보상 모델의 점수는 A가 2, B가 1이라고 하자.

rA−rB=2−1=1

보상 모델이 선호 답변 A에 B보다 1점 높은 점수를 준 상태다.

σ(1)=11+e−1≈0.731059

점수 차이를 사람이 A를 선호할 예측 확률로 바꾼다.

LRM=−lnσ(1)≈0.313262

실제 선택이 A였으므로 그 선택의 확률에 음의 로그를 취한다. A의 선호를 더 잘 예측할수록 이 손실은 작아진다.

6.7.2. 기대 보상

기대 보상은 현재 모델이 답변을 생성할 때 받을 보상의 평균적인 값이다.

E[r]=∑ypyry
  1. py는 답변 y를 생성할 확률, ry는 그 답변의 보상이다.
  2. 확률과 보상을 곱해 모두 더한다. E[r]는 이렇게 구한 기댓값을 뜻한다.

예시 · 두 답변의 평균 보상

가능한 답변이 A와 B뿐이고, 확률은 0.6과 0.4, 보상은 2와 1이라고 하자.

0.6×2=1.2

A가 나올 확률과, A가 나왔을 때 받을 점수를 함께 반영한 값이다.

0.4×1=0.4

같은 방식으로 B가 평균 보상에 기여하는 부분을 계산한다.

E[r]=1.2+0.4=1.6

두 기여를 더하면 현재 모델이 답변을 생성할 때 받을 평균적인 보상이 된다.

6.7.3. KL 페널티

KL 페널티는 보상을 높이려다 기준 모델과 크게 달라지는 변화에 비용을 붙이는 것이다.

DKL=∑ypylnpyqy
J=E[r]−λDKL

  1. py는 현재 모델, qy는 고정된 기준 모델의 답변 확률이다. pyqy는 기준에 비해 그 답변의 확률이 몇 배가 됐는지 나타낸다.

  2. 로그 비율은 두 음의 로그 손실의 차이다.

    ln(pyqy)=(−ln(qy))−(−ln(py))

    현재 모델이 내는 답변을 기준 모델의 확률로 평가할 때, 음의 로그 손실이 얼마나 더 드는지 비교한다.

  3. 현재 모델이 자주 내는 답변을 더 반영하도록 py를 곱해 평균낸다. 그 비용을 기대 보상에서 뺀 J를 최대화한다.

페널티가 없다면 보상 점수만 좇으며 기준 모델의 행동에서 크게 벗어날 수 있다. 예를 들어 보상 모델이 긴 답변을 좋아하면, 모델이 불필요한 반복으로 점수를 올릴 수 있다.

λ는 KL 비용에 얼마나 큰 비중을 둘지 정하는 계수다. λ=0이면 페널티가 없고, 클수록 기준 모델을 강하게 유지하려 하며, 작을수록 보상을 높이기 위한 변화를 더 많이 허용한다.

예시 · 분포 변화에 비용 붙이기

현재 확률은 [0.6,0.4], 기준 확률은 [0.5,0.5]라고 하자.

0.6×ln0.60.5≈0.109393

A의 확률은 기준의 1.2배다. 그 로그 변화에 현재 A의 생성 확률을 곱해 반영한다.

0.4×ln0.40.5≈−0.089257

B의 확률은 기준의 0.8배라서 로그가 음수다. 개별 항은 음수가 될 수 있다.

DKL≈0.109393+(−0.089257)≈0.020136

두 항을 더한 값이 현재 분포와 기준 분포의 차이다. 전체 KL은 0 이상이다.

앞의 기대 보상 1.6과 λ=1을 사용하면:

J=1.6−1×0.020136≈1.579864

기대 보상에서 분포 변화의 비용을 뺀 최대화할 목표값이다. 여기서는 페널티 강도가 1이므로 KL 값만큼 뺀다.

KL은 두 분포가 같으면 0이다. 답변의 정확성을 직접 판정하는 값은 아니다.

6.7.4. Advantage

Advantage는 어떤 선택의 결과가 예상보다 얼마나 좋았는지 나타내는 값이다. 한 번 선택하고 끝나는 예제에서는 다음처럼 구한다.

A^=G−V
  1. G는 이후의 보상과 보정을 반영한 return, V는 가치 모델의 예상값이다. 실제 결과에서 예상값을 뺀다.
  2. 양수면 예상보다 좋았고, 음수면 못했다는 뜻이다. 실제 여러 토큰의 PPO에서는 보통 GAE로 추정한다.

예시 · 실제 결과와 예상의 차이

별도의 한 번의 선택 예제로, 보정된 return이 2이고 예상값이 1.5라고 하자.

A^=2−1.5=0.5

예상보다 0.5만큼 좋은 결과였으므로, 같은 선택의 확률을 높이고 싶은 상황이라는 신호다.

6.7.5. PPO 정책 손실

PPO 정책 손실은 좋은 선택의 확률을 높이되, 한 번 모은 데이터로 지나치게 바뀌는 것을 조절하는 기준이다.

ρ=pcurrentpold
Lactor=−min(ρA^,clip(ρ,1−ε,1+ε)A^)
  1. ρ는 같은 선택의 현재 확률을 이전 정책의 확률로 나눈 비율이고, A^는 advantage다.
  2. clip은 비율을 [1−ε,1+ε]로 자른다. 원래 비율과 자른 비율에 각각 advantage를 곱한다.
  3. 두 값 중 작은 값을 고르고 마이너스를 붙인다. 좋은 방향으로 충분히 변한 선택에는 추가 이득을 주지 않는 방식이다.

예시 · 확률 비율과 clipping

이전 확률은 0.6, 현재 확률은 0.78이고, A^=0.5, ε=0.2라고 하자.

ρ=0.780.6=1.3

이 선택의 생성 확률이 이전 정책의 1.3배가 됐다는 뜻이다.

clip(1.3,0.8,1.2)=1.2

설정한 상한 1.2를 넘었으므로, 비교에 사용할 두 번째 비율은 1.2로 자른다.

1.3×0.5=0.651.2×0.5=0.60

좋은 결과였다는 신호를 두 비율에 곱해, 원래 목표와 clipping한 목표를 비교한다.

Lactor=−min(0.65,0.60)=−0.60

작은 값 0.60을 고르고, 최소화할 손실로 바꾸기 위해 부호를 뒤집는다. 이 항에서는 비율을 더 높여도 추가 이득이 없다.

이전 정책은 데이터를 생성한 모델이고, KL의 기준 모델은 고정된 SFT 모델이다. clipping은 실제 확률을 강제로 구간 안에 고정하지 않는다.

6.7.6. 가치 모델 손실

가치 모델 손실은 앞으로 받을 return을 더 정확히 예상하도록 학습하는 기준이다.

Lvalue=(V−G)2
  1. 예측값 V에서 목표 return G를 뺀 뒤 제곱한다.
  2. 예측이 목표에 가까워질수록 손실이 작아진다. 여러 경험에서는 이 값을 평균한다.

예시 · 예측 오차를 손실로

예측이 1.5이고 목표가 2라면:

V−G=1.5−2=−0.5

이번 결과를 실제 목표보다 0.5 낮게 예상했다는 뜻이다.

Lvalue=(−0.5)2=0.25

오차를 제곱해 크기를 평가한다. 이 손실을 줄여 가치 모델이 이번 목표에 더 가까운 값을 예상하도록 학습한다.

KL을 보상에 반영했다면 return과 advantage에도 그 영향이 들어간다. 같은 페널티를 무조건 다시 더하지 않도록 구분한다.

6.8. DPO: 두 답변의 선호를 직접 배우기

DPO는 사람이 선호한 답변 쪽으로 상대적인 확률 비율이 이동하도록 언어 모델을 직접 학습하는 것이다.

d=lnpAqA−lnpBqB
LDPO=−lnσ(βd)

여기서 pA, pB는 현재 모델, qA, qB는 기준 모델의 선호·비선호 답변 확률이다.

  1. 기준 대비 변화: pAqA와 pBqB로 각 답변의 확률이 기준의 몇 배가 됐는지 본다.
  2. 두 변화의 비교: 두 비율의 로그 차이 d는 선호 답변 쪽으로 상대적인 비율이 얼마나 이동했는지 나타낸다. 두 변화율이 같으면 0, 선호 쪽 변화율이 더 크면 양수다.
  3. 선호 확률로 변환: 양수 계수 β로 차이의 척도를 조절하고 sigmoid를 적용한다. 이 값은 현재·기준 모델의 확률 관계가 A를 선호하는 비교 결과를 얼마나 지지하는지 나타낸다.
  4. 손실로 변환: 그 확률에 음의 로그를 취한다. A의 선호를 더 잘 지지할수록 손실이 작아진다. 이 손실로 현재 모델만 학습한다.

예시 · 두 답변의 변화 비율 비교

A의 현재·기준 확률은 0.6·0.3, B는 0.2·0.4이고, β=1로 둔다.

A의 변화율은 0.60.3=2, B는 0.20.4=0.5다. 기준에 비해 A는 2배, B는 절반이 됐다.

d=ln(2)−ln(0.5)=ln(4)

두 변화율의 비율은 20.5=4다. 즉 A와 B의 생성 확률 비율이 기준 모델의 4배가 됐다는 뜻이다.

σ(ln(4))=0.8

이 차이를 sigmoid에 넣으면 선호 관계에 부여한 확률이 0.8이 된다. A 자체의 생성 확률 0.6과는 다르다.

LDPO=−ln(0.8)≈0.223144

선호 관계에 높은 확률을 줬으므로 손실은 약 0.223144다. 이 값을 더 낮추는 방향으로 모델을 학습한다.

여러 토큰의 답변은 응답 토큰의 로그 확률을 합산해 평가한다. 원래 DPO에서는 이 합을 토큰 평균으로 바꾸지 않는다. 기준 모델은 고정하며, 직접 학습하는 대상은 두 답변의 상대적인 관계다.

6.9. 마치며

최근 학교에서 인공지능 수학을 공부하고 있는데, 이번 활동은 그 수학을 왜 배우는지 한 번에 와닿게 해주는 활동이었다. 행렬 연산으로 모델의 출력을 만들고, 확률을 이용해 손실을 계산하는 과정을 따라가면서 수업에서 배우는 내용이 어디에 쓰이는지 연결해 볼 수 있었다.

Transformer를 공부하면서는 Self-Attention에서 이해되지 않는 부분이 많았다. 특히 Q, K, V는 솔직히 제대로 이해하지 못한 채 넘어가려고 했다.
