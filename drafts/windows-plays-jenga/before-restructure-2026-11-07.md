## 1. 배경과 문제의식

지난 수십년간 윈도우의 파일시스템에 관해 수많은 취약점이 보고되어왔다. 이에 대해 마이크로소프트는 보안 원칙보다 하위 호환성, 사용자 편의성에 중점을 두어 각 취약점에 대해 개별 패치를 진행해왔다. 이는 불안전한 기반 위에 젠가를 쌓는것과 비슷하다. 이 연구는 이러한 패치는 지속적으로 문제가 발생할 수 있으니 윈도우 파일 시스템에 대한 근본적인 변화가 필요하다고 본다.

## 2. 핵심 아이디어

이 연구의 핵심 아이디어는 윈도우 파일 시스템에서 반복되는 취약점을 설계와 동작 방식의 관점에서 살펴보는 것이다. 저자들은 리눅스를 비교 기준으로 삼아, 같은 파일 작업이 두 운영체제에서 어떻게 다르게 처리되는지 분석했다. 이를 통해 개발자가 예상하는 동작과 윈도우에서 실제로 일어나는 동작 사이의 차이가 보안 문제로 이어질 수 있다는 점에 주목했다.

또한 이러한 차이를 운영체제 수준에서만 살펴보는 데 그치지 않고, 실제 프로그램과 프로그래밍 언어의 호환 계층, 개발자의 이해와 대응까지 연결해 분석했다. 이를 통해 문제가 발생하는 원인부터 기존 대응책으로 충분히 해결되지 않는 이유까지 살펴보고자 했다.

## 3. 방법론 — 무엇을 어떤 순서로 확인했을까

### RQ1. 윈도우와 리눅스 파일 시스템의 차이 분석

저자들은 두 운영체제의 파일 시스템을 링크 추적, 파일 잠금, 파일 권한이라는 세 가지 측면에서 비교했다.

#### 1. 파일 링크 추적의 차이

파일 작업을 수행할 때 링크를 처리하는 방식이 운영체제와 링크 종류에 따라 달라지는지 확인했다.

- 비교 대상: 리눅스 심볼릭 링크, 윈도우의 NTFS 심볼릭 링크, JDSymlink
- 비교 작업: 파일 열기·삭제·이름 변경
- 확인한 내용: 각 작업이 링크 자체에 적용되는지, 링크를 따라가 대상 파일에 적용되는지 비교했다. 파일을 열 때는 링크 추적 방지 옵션을 지정한 경우에도 링크를 따라가는지 확인했다.

#### 2. 파일 잠금의 차이

운영체제별 파일 잠금 방식이 다른 프로세스의 파일 접근과 프로그램의 동작에 어떤 영향을 미치는지 비교했다.

- 비교 대상: 윈도우의 강제적 잠금(mandatory locks)과 리눅스의 협력적 잠금(advisory locks)
- 비교 항목: 잠금을 사용하지 않는 프로세스의 접근도 제한하는지, 잠금 조건과 충돌하는 파일 작업이 실패하거나 지연되는지
- 확인한 내용: 낮은 권한의 프로세스가 설정한 잠금이 높은 권한의 프로그램에 오류나 지연을 일으킬 수 있는지 살펴봤다. 또한 이러한 오류와 지연이 프로그램의 대체 처리나 실행 순서에 영향을 주어 보안 문제로 이어질 가능성을 분석했다.

#### 3. 파일 권한 상속의 차이

파일과 디렉터리를 생성할 때 권한이 결정되는 방식과, 부모 디렉터리의 권한이 새로 생성된 파일에 어떤 영향을 미치는지 비교했다.

- 비교 대상: 윈도우와 리눅스의 파일·디렉터리 생성 시 권한 설정 방식
- 비교 항목: 생성 주체와 부모 디렉터리의 권한이 새 파일의 접근 권한에 미치는 영향, 권한 상속을 제어하는 방식
- 확인한 내용: 높은 권한의 프로그램이 임시 디렉터리에 파일이나 디렉터리를 생성할 때, 부모 디렉터리의 권한을 상속받아 일반 사용자에게 의도보다 넓은 접근 권한을 허용할 수 있는지 살펴봤다. 또한 이러한 권한 설정이 파일 조작 등 보안 문제로 이어질 가능성을 분석했다.
